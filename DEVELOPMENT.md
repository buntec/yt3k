# Developing yt3k

## Running

```sh
npm install
npm run dev
```

Then, once: `chrome://extensions` → enable **Developer mode** → **Load unpacked** →
select `.output/chrome-mv3-dev`. While `npm run dev` runs, the extension reloads on
save. The dev build has its own extension ID (and an orange icon), so it runs
alongside an installed release with separate data.

A local, gitignored `web-ext.config.ts` with `disabled: true` stops WXT from
launching a separate browser profile, so you stay logged in to YouTube.

`npm run build` produces `.output/chrome-mv3` for use without the dev server. It has
the release's ID, so it replaces an installed release.

For Firefox, `npm run dev:firefox` and `npm run build:firefox` write
`.output/firefox-mv3-dev` and `.output/firefox-mv3`. Load one via `about:debugging` →
**This Firefox** → **Load Temporary Add-on** → its `manifest.json`. Firefox drops it
on restart; until then, the `build:firefox` one replaces an installed release. Its
button starts in the Extensions (puzzle-piece) menu; pin it from there.

## Tests and tooling

`npm test` runs the parser tests against anonymized YouTube data in
`utils/__fixtures__/`, whose README explains how to capture fresh data when YouTube
changes.

`npx astryx` prints component docs, e.g. `npx astryx component Button`.
`astryx-themes.ts` is generated by `npx astryx theme add`; don't edit it by hand.

## Google Drive sync

Sync uses a file in the Drive app data folder (scope `drive.appdata`). Each browser
keeps all groups and merges its copy with the file: for a group changed on two
devices the last change wins, deletions are remembered for a year so they reach other
devices, and same-named groups created on two devices before syncing merge into one.
Podcasts behave the same way: one removed on one device is removed on the others,
and following it again brings it back. A browser receiving a podcast still needs
permission to read its feed's site, which the Podcasts tab asks for.

The file format changed when podcasts were added; older versions stop syncing until
updated rather than drop podcasts. Firefox asks to allow sending "website activity"
when sync is turned on, and sync stops if that's revoked in `about:addons`. **Turn
off sync** doesn't revoke access, since that would stop every browser on the same
Google account.

Builds without an OAuth client ID leave sync out; dev builds then explain how to add
one. To set one up:

1. In the [Google Cloud console](https://console.cloud.google.com/), create a project
   and enable the **Google Drive API**.
2. Under **Google Auth Platform**, configure the consent screen (app name, support
   email, and for publishing, a home page and privacy policy link), and add the
   `.../auth/drive.appdata` scope under **Data access**. While the app is in
   **Testing**, add the accounts that may sign in under **Audience**.
3. Under **Clients**, create a **Web application** client with these **Authorized
   redirect URIs**. Each build logs its own to the yt3k page's console on open, and a
   dev build without a client ID also shows it from the cloud button in the top bar:
   - Chrome and Edge release: `https://jjaoknknijpnllfipmgibppilgojikej.chromiumapp.org/`
   - Firefox release: `https://ec6355757a5df7e685ed9f07bbda4015cf45c770.extensions.allizom.org/`
   - Firefox dev build: `https://ab4444a0dd90e69489a7de4f30ed59af513c7c2e.extensions.allizom.org/`
   - Chrome dev build: the URI it logs, which depends on its folder

   Firefox's derive from the SHA-1 of the add-on ID, so they're stable across
   machines as long as the IDs in `wxt.config.ts` are.
4. Put the client ID in `.env` as `WXT_GOOGLE_CLIENT_ID`. It isn't secret; it ships
   in the built extension.

## Releasing

Pushing a tag like `v1.2.3` runs the release workflow, which builds for Chrome, Edge
and Firefox with that version and publishes a GitHub release (the version in
`package.json` is ignored). `just release 1.2.3` runs the CI checks, then tags and
pushes.

To sign the Firefox `.xpi`, add [addons.mozilla.org](https://addons.mozilla.org/developers/addon/api/key/)
API credentials as the repository secrets `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`. The
workflow then signs it for self-distribution (unlisted) and publishes the
`updates.json` that installed copies check for updates.
